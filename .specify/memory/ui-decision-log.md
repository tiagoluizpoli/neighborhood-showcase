# UI Decision Log

| Date | Area | Current state | Proposed change | Impact | Decision |
| --- | --- | --- | --- | --- | --- |
| 2026-06-03 | Public browsing shell | Public portal routes use the shared app-style header with authenticated app controls, and footer navigation is not aligned with the public shell. | Replace public browsing shell navigation with dedicated public header/footer for `/`, `/anuncios/:id`, and `/prestadores/:id`; keep `/auth` focused; keep `/panel/*` separate; avoid legal dead links. | Visitors get public browsing navigation instead of private app navigation, while Providers still have `Entrar` or `Painel` access. | Approved; tracked in Issue 56. |
| 2026-06-03 | Home location control | Home page auto-opens geolocation prompting and uses large first-viewport location bars; non-denial browser failures can be treated as refusal; manual selection is condominium-only. | Switch to browse-first behavior with one compact location/status control, explicit confidence states, transparent session-only IP region fallback, GPS refresh after prior grant, and manual region/condominium selection. | The first viewport stays focused on browsing while location relevance remains available, error states become truthful, and Visitors can manually browse by area or condominium. | Approved; tracked in Issue 57. |
| 2026-06-03 | Home discovery layout | Home browsing is constrained to a centered column with stacked controls, leaving desktop side space unused and pushing the feed down. | Use a full-width discovery layout with compact hero, compact controls, responsive dense grid, and real `#explorar`, `#como-funciona`, `#anunciar` sections. | The home page becomes a browsing-first marketplace surface while still supporting light landing-page explanation and provider CTA. | Approved; tracked in Issue 58. |
| 2026-06-03 | Announcement card | Current card is functionally complete but noisy, inline in the home route, and prioritizes administrative metadata over the offer. | Use Spectrum UI Product Card as a visual reference, adapted for announcements with offer-first hierarchy, provider trust, one primary contact action, and accessible whole-card navigation. | Announcement cards become the main polished repeated object of the marketplace feed without importing ecommerce assumptions. | Approved; tracked in Issue 59. |
| 2026-06-03 | Announcement detail navigation | Home page manually pushes `/anuncios/:id`, stores active detail state, and renders a duplicate preview modal despite a real detail route existing. | Remove the home-page modal hybrid and make `/anuncios/:id` the only full detail rendering and impression-tracking surface. | Navigation, analytics, and detail rendering have one owner, reducing duplicated UI and route-state bugs. | Approved; tracked in Issue 60. |
| 2026-06-03 | Home feed states | Feed loading uses a centered spinner, empty state is generic, and query failures are not clearly separated from no results. | Use feed-shaped skeletons, contextual empty states, explicit retryable error state, and keep discovery controls visible throughout. | The browsing surface remains stable and actionable even when data is loading, absent, filtered out, or temporarily unavailable. | Approved; tracked in Issue 61. |
